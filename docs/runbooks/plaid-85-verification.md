### Proposed runtime comparator — review required, not implemented

Question: obtain R02/R03 evidence without exposing source records or granting a
worker general ledger access. Proposed owner: #88/#85, coordinator review pending.
This is an operational verification protocol, not an ISO20022 financial message;
existing proprietary Plaid API2020-09-14, ISO4217 currency and date assessment apply.
No new accounting or conformance claim.

Prefer a separate, explicit, Sandbox-only one-shot verifier identity over an API
route or widening sync worker privileges. New forward migration required before
implementation; immutable merged migrations stay untouched. It gets EXECUTE only
on two new fixed security-definer functions, no table SELECT or posting grants,
no role membership in owner/API/sync/publisher. Validate session/current identity,
NOINHERIT and forbidden mixed memberships exactly as existing runtime probes.
No bypass through caller-supplied actor IDs. Current authorization uses a separately
owner-installed finite mandate binding verified service login, exact
entity/book/source/Item/account/namespace, expected completed generation and
expiry; recheck at every call. Revocation/expiry/foreign scope fail closed. Never
accept arbitrary SQL, DSN, object path, raw payload or unrestricted account list.

1. `verification_snapshot(mandate_id)` executes a single read-only snapshot and
   returns only bounded counters/revisions: source revision, current generation,
   completion state, all-book journal count and journal-posting outbox count,
   plus a random verification nonce. It does not return transaction fields.
   Before/after measurements must pin the same mandate and book. Counts alone
   cannot establish causation under concurrent manual posting: require an explicit
   isolated test window and record that limitation. It must neither persist the
   receipt nor enqueue an event; output is collected as a redacted run artifact.
2. `verification_compare(mandate_id, expected_fixture)` accepts at most the existing
   1,000-change/2MiB bound, rejects duplicate fixture identities, and compares the
   complete authorized source projection, revisions and exact provider lexemes,
   currency IDs/codes, dates, state, direction and pending lineage against an
   independently authored fixed fixture. Include retained history when expected,
   not only the latest pointer. Check review evidence through its authorized
   projection as well. Return total and per-field mismatch *counts*, complete-set
   equality and fixed error codes only; never values, IDs, names or hashes that
   could disclose small amounts. The fixture is ephemeral input, never logged,
   persisted, retained in a command, or echoed. Secret/raw-provider payloads are
   not an allowed fixture source. For hosted use start with named custom synthetic
   transactions, independently specified before provider injection.

The CLI must be inert by default and require explicit operation, manifest and
mandate; finite timeout, one attempt, no automatic provider sync, no credential
file/environment scanning and no default cloud operation. Bind redacted results
to reviewed image/build, schema version, manifest digest and observation time.
Snapshot race/expired mandate and unknown outcome fail evidence, never silently
retry as a pass. No mechanism may authorize a posting or mutate source data.

Acceptance before hosted execution: restricted-role disposable PG tests deny
wrong/revoked/expired mandate, foreign entity/book/source, mixed roles, oversized
fixtures and unknown fields; demonstrate unit/date/state/lineage mismatch detection
and missing/extra/duplicate identities; demonstrate no sensitive outputs; unchanged
journal/outbox zero for acquisition and replay. Trigger a controlled synthetic
journal addition in the disposable DB to prove counters detect it. Production
mandates must be rejected. Retain failed comparator evidence as fixed reasons.

Alternative: owner-run arbitrary SQL/dumps are quicker but violate the narrow
runtime/privacy boundary. Reusing worker authority for ledger reads couples
acquisition to posting evidence and unnecessarily expands its privilege. A public
comparison endpoint expands sensitive input and authorization surfaces. Deferred
one-shot scoped functions add migration/review work but give inspectable least
privilege and exact reproducible proof. Neither this proposal nor source review
approves that migration or authorizes hosted execution.
