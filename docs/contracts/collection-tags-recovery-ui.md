# Collection tags and owner recovery UI

Implements the UI portion of [the frozen tag/recovery contract](collection-tags-recovery.md), alongside [live labels](collection-live-labels.md). Source discovery remains v1; collection catalog/query/preview/command routes use v2. Every new snapshot and selector carries the tag revision/filter. Saved command previews preserve their explicit historical v1 or v2 shape without inventing missing tags or revisions.

Strategic tags are separate from the primary topic. Catalog changes preserve stable identities and terminal retirement. Add/remove/replace acts only on explicit selected composite workspace/source/observation identities, at most 100. The server returns exact reviewed resulting sets. Stale prior tags require explicit replacement; replacing with zero tags explicitly clears that set. The bounded, searchable checklist retains selected IDs when filtering and exposes its selected count outside the scroll area. Every operation follows preview, save, explicit confirmation and explicit acknowledgement; no browser financial persistence is used.

`CollectionRecovery` mounts outside scoped workspace discovery. Props are `api`, optional `refreshVersion`, `onLockChange`, `onAvailable`, `onCleared` and `onStateChange`. The granular callback reports `{state, uncertain, canReview}`. `canReview` requires available authority for either no clear candidate or the same exact candidate. Checking/unavailable callbacks do not prove closure. Parent mounting retains prior eligibility during transient checks; positive inaccessible or different available identity suppresses scoped payload. `onAvailable` is identity/edge driven. `onCleared` fires only for the exact closure receipt after an explicit action.

Global recovery exposes no workspace, financial payload, command state or opaque identity in the UI. Unknown clear retains its exact candidate across status none, later 404 or another claim. A same-ID receipt may prove closure by explicit ordinary acknowledgement elsewhere; it never clears newer work. Initial feature-off 404 is feature absence only before known work. Subsequent failures keep new work locked. Recovery creates no grant.

`CollectionWorkspace` accepts `newWorkLocked` separately from the actual book command gate. It prevents new selection/preview/save intent while existing explicit execute/cancel/acknowledge and exact uncertain save retry remain possible. `onRecoveryNeeded` fires at scoped denial so the parent refreshes global discovery; private rows and previews are destroyed. A lost save response retries its exact key even after preview expiry, since only the server can determine whether that save exists.

Synthetic component tests do not establish production authority or managed rollout. The coordinator owns shared parent mounting and actual SQL/HTTP/browser integration evidence.
