Merchant literal filters use case-insensitive matching, distinct from the rule evaluator's case-sensitive conditions. Amount bounds are nonnegative exact decimal strings, optionally inclusive minimum/maximum, within one selected dated currency. Feedback validates lexical bounds, nonzero fractional precision and ordered bounds with integer arithmetic; it never rounds or converts. Amount sorting groups original currency code/version before magnitude, with unavailable money last. No cross-currency FX comparison or financial total is fabricated. Institution remains unavailable and legal owner unknown until separately evidenced metadata exists; neither is inferred from account names or book entities.

Every journal anchor is unique and canonical, belongs to an assigned readable book, and carries its actual positive historical source revision. The frontend rejects mismatched pins or forbidden anchors before rendering.

Explicit journal anchors use an injected existing authenticated book-journal read; its exact entity/book/journal identity is rechecked and original/functional decimal strings remain separate. No posting, reversal or draft controls are introduced. Denial destroys detail/page state; superseded responses cannot repopulate another scope. Read failures offer retry or Back without inventing empty results.

## Rule profile

The integrated UI now uses v3 catalog/query/detail/preview/command routes. Persisted previews remain an explicit v1/v2/v3 union; no missing tag, origin or rule fields are synthesized into old receipts. Every version keeps its original pins and immutable review content. New v3 preview review_rows retain the existing v2 row shape with current effective values; rule results are separate. The validator rejects v3 read metadata in all saved review rows.

A complete rule edition retains stable IDs, terminal retirement and up to 1000 entries/100 active rules. Active names are case-sensitive unique and bounded to 80 codepoints. Each rule has explicit account/workspace scope, integer priority, 1–8 conjunctive conditions and one active primary topic or explicit Uncategorized with at most 20 active output tags. Condition values are bounded to 128 UTF-8 bytes. The browser never compiles or evaluates rule regex; Go remains the only matcher. Rule arrays are capped at 256 KiB without truncation, with authoritative complete-response admission enforced by the server. Condition order is preserved; rule IDs and output tag sets canonicalize for request/preview comparison.

The editor mounts only one rule's controls/tag checklist at a time, with a bounded searchable tag region. Catalog edits and explicit 1–100 selected historical applications share preview, save, confirmation/cancellation and acknowledgement. The exact per-row will_apply flag determines the server's apply/abstain counts; these are checked against the bounded selected result list, never a query page or whole-query estimate. Current manual topic and tags remain independently protected; a stale manual field abstains the entire row, both manual fields override, and equal-rank conflict produces no chosen output. Effective result tags may reach 25 only when the manual tag field is preserved.

Current values, saved rule_application provenance and inert rule_suggestion are shown separately. Saved origin carries its own ruleset/rule revisions and current/stale/superseded state; a current suggestion never proves an older label's origin or application eligibility. Query/detail suggestions always have will_apply=false. Old decisions are historical evidence and are never relabeled manual or rewritten on read.

It retains an inert seed bound to the same workspace, command and prepare key while acknowledgement is unknown; no editor opens before the exact confirmed acknowledgement.
