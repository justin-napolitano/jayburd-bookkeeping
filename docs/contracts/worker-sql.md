**Proposed physical contract, not DDL or implemented behavior**, 2026-10-13;
owner: project maintainer; [#74](https://github.com/justin-napolitano/jayburd-bookkeeping/issues/74),

## Concrete authorization and roles

Propose NOLOGIN roles `bookkeeping_publisher` and `bookkeeping_observer`, neither
member of API/owner/migrator/identity-operator or each other. Separate actual
workload login roles receive exactly one role. Cloud Tasks invocation identity
is not a database login and receives no SQL grant. HTTP middleware still verifies
configured OIDC issuer/audience/service identity before invoking observer SQL.

`integration.observer_binding` is owner-provisioned, not a self-enrollment API:

| Column | Type and constraint |
| --- | --- |
| binding_id | uuid PRIMARY KEY |
| entity_id, book_id | uuid NOT NULL; composite FK to `ledger.book`, NO ACTION |
| principal_id | uuid NOT NULL FK `ledger.principal`, NO ACTION; dedicated service principal, not original poster |
| publisher_login, consumer_login | name NOT NULL; distinct; exact PostgreSQL `session_user` login names |
| consumer_id, handler_version | text CHECK = `journal.observe`; integer CHECK = 1 |
| binding_revision | bigint NOT NULL CHECK > 0 |
| enabled | boolean NOT NULL |
| created_at, updated_at | finite timestamptz NOT NULL |

UNIQUE `(entity_id,book_id,consumer_id,handler_version)` and UNIQUE
`(entity_id,book_id,binding_id)`. Binding IDs/scope/principal/consumer/version/login
names never mutate; enable/disable increments revision. Changing identity needs a
future explicit handoff contract, not assigning old work to a new login silently.
Only the provisioning owner controls binding rows, creates the ledger principal
and supplies `read` membership for its entity. No invented `observe` permission
is inserted into the existing membership CHECK. Binding additionally narrows that
entity-level membership to one book; database functions never accept actor input.
Do not mint Firebase tokens or interpret end-user email as service identity.
The exact synthetic/hosted enrollment procedure is a prerequisite to DDL rollout.

All callable functions are owned by `bookkeeping_owner`, SECURITY DEFINER,
VOLATILE/PARALLEL UNSAFE, `SET search_path=pg_catalog,pg_temp`, fully qualified
relations/functions. Revoke PUBLIC EXECUTE in the same migration transaction;
only grant named entrypoints below. No direct table SELECT/DML, sequence access,
schema CREATE, role elevation or execution of internal helpers for either role.
Require SERIALIZABLE for every mutating entrypoint. Set transaction-local
statement_timeout=5s and lock_timeout=1s before invocation; tests verify safe
failure when callers omit required transaction mode. Functions set their own
lock timeout defensively; handler's SQL context bounds the entire call.

Resolve immutable operation→binding metadata, then require the function-specific
`session_user` to equal the enrolled publisher/consumer. Do not trust `current_user`
inside SECURITY DEFINER or a caller-supplied worker UUID as principal authority.
Recheck binding and call `ledger.authorize(principal_id,e,b,'read',false)` in the
same SERIALIZABLE transaction, taking the existing principal/entity/membership/book
locks. Map P2101/P2102 to the uniform worker denial below, without scope disclosure.
The service principal must remain enabled with current read membership at discovery,
claim and completion. Posting-user revocation does not cancel independent authorized
observation. Deletion of referenced principals is **not solved** here: current FKs
restrict deletion, and #4's deletion-policy/testing gap remains open.

## Proposed rows, keys and indexes

All columns NOT NULL unless explicitly `nullable`. UUIDs are generated by the
server. All timestamps finite; all counters bigint and nonnegative with guarded
overflow. Repeated scope columns use composite FKs; no cascading deletes. Owner
triggers reject updates/deletes of immutable sidecars, attempts and receipts.
Allowed table names are in `integration`; these are specifications, not SQL files.

### work_operation

`entity_id uuid, book_id uuid, operation_id uuid, binding_id uuid,
message_id uuid, consumer_id text='journal.observe', handler_version integer=1,
request_digest bytea CHECK octet_length=32, created_at timestamptz,
state text, attempt_count bigint DEFAULT 0, failed_attempt_count bigint DEFAULT 0,
execution_generation bigint DEFAULT 0, fence_token bigint DEFAULT 0,
dispatch_generation bigint DEFAULT 1, next_eligible_at timestamptz,
first_claimed_at timestamptz nullable, deadline_at timestamptz nullable,
lease_holder uuid nullable, lease_until timestamptz nullable,
claim_binding_revision bigint nullable, terminal_code text nullable,
finished_at timestamptz nullable`.

PK `(entity_id,book_id,operation_id)`; UNIQUE `operation_id`; UNIQUE
`(entity_id,book_id,message_id,consumer_id,handler_version)`. Composite FKs to
binding and outbox message. CHECK consumer/version constants; state in
`ready,running,retry_wait,succeeded,blocked,quarantined`.
`failed_attempt_count <= attempt_count`; `execution_generation=attempt_count`.
First claim sets first_claimed_at once and deadline_at=first_claimed_at+24h;
CHECK both null together, otherwise exact interval. Running iff holder, lease and
claim revision all nonnull; lease bounded by its attempt's start+90s. Succeeded/
blocked/quarantined iff terminal_code and finished_at nonnull. Code CHECK uses
closed list `observed,authority_revoked,event_mismatch,retry_exhausted,age_exhausted`.
Success code is `observed` only; blocked code is `authority_revoked`; quarantine
codes are `event_mismatch,retry_exhausted,age_exhausted`. Cross-row/state correspondence is owned-function
plus deferred constraint-trigger authority, not an unsupported CHECK subquery.
No opaque financial JSON body or runtime-selectable handler.

`request_digest` uses SHA-256 over UTF-8 with fixed ASCII delimiter `|` and these
canonical values: `journal.observe|1|entity_uuid|book_uuid|message_uuid|target_uuid|book_revision`.
UUIDs lowercase canonical; revision unsigned decimal. These fields cannot contain
`|`. Compute server-side with pg_catalog SHA-256 support; compare all source fields
as well as digest when resuming. Digest is an accelerator/integrity check, not
business identity. Binding configuration/retry counters are not source identity.

Indexes: partial `(next_eligible_at,operation_id)` for ready/retry_wait;
partial `(lease_until,operation_id)` for running; `(binding_id,state,operation_id)`
for scoped recovery. UNIQUEs above enforce deduplication across dispatch generations.
No assumption of contiguous journal revisions or event order.

### outbox_delivery

`entity_id uuid, book_id uuid, message_id uuid, consumer_id text='journal.observe',
handler_version integer=1, operation_id uuid, created_at timestamptz`.
PK `(entity_id,book_id,message_id,consumer_id,handler_version)`; UNIQUE
`(entity_id,book_id,operation_id)`; scoped FK to existing outbox; composite FK of
scope/message/consumer/version/operation to a matching UNIQUE on work_operation.
Immutable sidecar. Insert operation, sidecar and dispatch 1 atomically. Existing
outbox facts remain unchanged even when no consumer is enrolled.

### work_dispatch

`entity_id uuid, book_id uuid, operation_id uuid, dispatch_generation bigint CHECK >0,
target_version integer CHECK =1, task_name_digest bytea CHECK octet_length=32,
state text, enqueue_attempt_count bigint DEFAULT 0, publisher_fence bigint DEFAULT 0,
lease_holder uuid nullable, lease_until timestamptz nullable, created_at timestamptz,
last_attempt_at timestamptz nullable, last_result_at timestamptz nullable,
result_code text nullable`.
PK scope/operation/dispatch_generation; FK to scoped operation. State in
`pending,publishing,enqueued,uncertain,retired`; publishing iff holder/lease nonnull.
Result nullable or `accepted,already_exists,timeout,transient,rejected`.
Task digest is SHA-256 of `operation_uuid|dispatch_generation|target_version`;
queue task ID uses its hex encoding. Target 1 resolves only through deployment
allowlist, never an arbitrary stored URL. UNIQUE task_name_digest. Partial index
`(created_at,operation_id,dispatch_generation)` for pending/uncertain; partial
`(lease_until,operation_id,dispatch_generation)` for publishing. Old rows are
retained as transport history; they cannot complete or revive work.

### work_attempt and work_receipt

Attempt columns: `entity_id uuid, book_id uuid, operation_id uuid,
execution_generation bigint CHECK >0, attempt_id uuid UNIQUE,
fence_token bigint CHECK >0, holder_id uuid, binding_revision bigint CHECK >0,
started_at timestamptz`. PK scope/operation/execution_generation; scoped operation
FK. Immutable start row. No later UPDATE to fill end-time fields; its matching
receipt supplies termination. UNIQUE `(entity_id,book_id,operation_id,
execution_generation,fence_token)` supports the receipt FK.

Receipt columns: `entity_id uuid, book_id uuid, operation_id uuid,
execution_generation bigint CHECK >0, fence_token bigint CHECK >0,
outcome text, request_digest bytea CHECK octet_length=32,
binding_revision bigint CHECK >0, recorded_at timestamptz`.
PK scope/operation/execution_generation; exact composite FK to attempt including
fence; outcome in `observed,retryable,abandoned,authority_revoked,event_mismatch,
retry_exhausted,age_exhausted`. Immutable. Unique partial index on
`(entity_id,book_id,operation_id) WHERE outcome='observed'` is the successful-effect
guard. Receipt binding_revision equals its attempt binding_revision (the authority
version captured by that execution); outcome distinguishes successful observation
from later revocation, not a claim that old authority remains valid.
Receipt has no journal amounts, tokens, provider bodies or caller-controlled
exception text. Journal provenance is reached through operation→outbox→journal.

An attempt starts once, then receives at most one outcome. Retry/failure closure
inserts outcome and increments failed_attempt_count in the same transaction under
operation lock; a competing scanner cannot count that attempt again. Pre-claim
blocked/quarantined decisions may have attempt_count=0, record terminal code/time
on operation and **do not fabricate an attempt or execution-0 receipt**. Their
fixed terminal acknowledgement is derived from the durable operation state.

## Lock order, clock and restricted functions

Every operation uses this order: immutable lookup without lock → binding FOR SHARE
(or UPDATE for owner disabling) → ledger principal → entity → membership → book
via authorize → work_operation FOR UPDATE → dispatch rows by ascending generation
→ attempt/receipt inserts. For recovery, process one scoped operation per transaction. Discovery may insert
up to 25 new operations for one authorized binding/book in event order; it never
locks an unordered collection of different books in one transaction. Candidate
selection is a nonauthoritative bounded read; acquire authorization locks before
`FOR UPDATE SKIP LOCKED` on operation/dispatch. Recheck predicates after lock.
Revocation transactions that touch binding and membership together follow this
same order. Existing membership-only revocation shares the authorize lock boundary.
No network operation runs while a SQL transaction remains open.

After all potentially waiting row locks, set `t=clock_timestamp()`; check lease
and deadline against **this** time. Lease validity requires `t < lease_until`.
Heartbeat cannot resurrect expiry. Increment counters/fences only after range
checks; exhaustion fails safely, never wraps. Dispatch and consumer fences are
independent. Changing a dispatch generation does not increase ledger revision.
Recheck actual time immediately before final state/receipt writes, after any
additional lock wait. Runtime commits immediately; no external await or user work
is allowed between the function return and COMMIT. Login-role transaction/idle
timeouts and handler context must bound open transactions during implementation.
Database wall-clock changes may affect liveness; generation fences plus locked
state still prevent a replaced holder from committing. Clock-based leases are
not a claim of a monotonic system clock.

All signatures below are under `integration`. `uuid` holder parameters identify
attempts, never authority. Functions return only the stated minimal metadata;
private helpers are not executable by runtime roles.

| Entry point / granted role | Exact inputs and returned values; owned transition |
| --- | --- |
| `observe_discover` / publisher | `(binding_id uuid, limit integer)`; require 1..25. Return integer inserted count only. entrypoint returning operation UUIDs only; limit 1..25, current scope authority,
ordered by next eligible time/UUID including expired claims/stale dispatches.
Discovery and candidates require explicitly configured binding IDs; no API to
enumerate every LLC. This read executes within SERIALIZABLE for consistent policy.
Role ACL tests must require SQLSTATE 42501 for every other function/table/DDL.

### Exact return shapes

The function table above is normative for inputs. These SQL return declarations
and closed statuses remove any implied free-form JSON result:

- observe_discover: RETURNS integer (0..25).
- observe_candidates: RETURNS TABLE(operation_id uuid), 0..25 rows.
- observe_dispatch_claim: RETURNS TABLE(status text, dispatch_generation bigint,
  target_version integer, task_name_hex text, publisher_fence bigint,
  lease_until timestamptz), exactly one row. Status is claimed or not_due;
  metadata all nonnull only for claimed, all null otherwise. task_name_hex is
  exactly 64 lowercase hex characters.
- observe_dispatch_result and observe_heartbeat: RETURNS boolean, never null.
- observe_claim: RETURNS TABLE(status text, execution_generation bigint,
  fence_token bigint, lease_until timestamptz), exactly one row. Status in
  claimed,done,busy,not_due; metadata all nonnull only when claimed. done includes
  durable succeeded/blocked/quarantined, exposing no outcome details.
- observe_finish: RETURNS text in observed,done. A newly observed receipt returns
  observed; existing completion or a newly committed block/quarantine returns done.
- observe_fail: RETURNS text in retry_wait,quarantined,done. A new retry/failure
  terminalization returns its state; prior terminal outcome or newly blocked
  authority returns done.
- observe_recover: RETURNS text in no_change,retry_wait,redispatched,blocked,
  quarantined,done. Return the most significant committed transition: terminal
  transition first, abandoned-attempt retry second, dispatch replacement third.
  Already terminal operation returns done; healthy/not-yet-due returns no_change.

These statuses apply only after transaction commit. Statement-level returns cannot
justify a task acknowledgement before COMMIT succeeds. SQL exceptions use the
separate error mapping below; they never masquerade as a returned terminal result.

## Completion, revocation and recovery transitions

The observer verifies outbox scope, target, event_type `journal.posted`, version 1
and revision equal the corresponding immutable journal header. A reversal journal
is eligible; its existing historical amounts are not recalculated or copied.
Mismatch closes an active attempt with event_mismatch and quarantines; it never
throws after writing the quarantine, which would roll back that evidence.

Authorization denial requires special handling: caller-login/binding existence is
checked first. Wrong caller sees uniform P2201 with no writes. A correctly enrolled
login whose previously bound service authority was revoked can only mark the
owned operation `blocked/authority_revoked`, clear its lease/increment fence and,
if running, close its attempt with authority_revoked. This restricted no-data
transition locks the same available principal/entity/membership/book rows even
when disabled/revoked, in the same order; it cannot read journal contents, enqueue,
claim or finish. Repeated denial adds no attempts or receipts. An already succeeded
operation returns only fixed `done` to its enrolled consumer even after revocation.
Only observe_claim, observe_finish, observe_fail and observe_recover own this
no-data blocking transition. Discovery, candidate enumeration and dispatch calls
deny with P2201 instead; heartbeat returns false after binding verification.
This is a receipt-suppression path, not permission to fetch its result.

Normal retry: with fewer than 8 failures and before first-claim+24h, clear lease,
set retry_wait and next_eligible_at=t+jitter. Delay range is
`[max(1s,B/2),B]`, `B=min(900s,5s*2^(failed_attempt_count-1))`; choose server-side,
never sleep in a transaction. This journal observer has no provider Retry-After.
At failure 8 quarantine with retry_exhausted; at deadline quarantine with
age_exhausted, whichever first applies. Successful completion must also occur
before the deadline. Claim, finish and recovery all evaluate deadline before
normal lease-contention handling. Deadline exhaustion closes any outstanding
attempt with age_exhausted (one failed count), fences its holder and atomically
quarantines, even if its lease has not yet expired; an already succeeded operation
stays succeeded. No new attempt is fabricated if none is outstanding.
Non-claim deliveries, denial and healthy lease contention
consume no attempt/failure budget. Event mismatch counts one failed attempt;
authority denial is a blocked outcome and consumes no failure budget.

On expired running recovery: under operation lock insert abandoned receipt if
no receipt exists for that execution, increment failed count once, clear holder,
advance fence, then apply same retry/cap rule. A new claim occurs only when due,
with a new execution generation. Heartbeats/finishes by the abandoned holder fail.
No attempt receipt exists yet for pre-claim age exhaustion; persist the operation's
terminal code instead. `succeeded`, `blocked` and `quarantined` never auto-reopen.

Recovery retires a current dispatch only when work is due, no healthy consumer
claim exists, and enqueue/result/create evidence is older than 15 minutes, or the
current transport attempt was explicitly rejected. Increment dispatch_generation
and insert pending dispatch atomically with retirement. An expired publisher lease
first permits retrying that same generation/task identity. ALREADY_EXISTS is
uncertain delivery evidence, never successful observation; queue deletion/purge
cannot erase SQL intent. Publisher result arriving after consumer completion may
update matching dispatch metadata but never regress succeeded work. Old queued
messages remain bound to the same operation and cannot create a second effect.

No cancellation or administrative retry endpoint is in this first slice. Preserve
terminal evidence for owner investigation; a later scoped audited budget-grant/
cancel contract is required to reopen/cancel work. Do not reset counters, edit
receipts or delete/recreate an operation to bypass exhaustion. Synthetic fixture
teardown drops the disposable database, not selected evidence rows. Hosted retention,
operator audit UI and deletion lifecycle remain deployment gates.

## SQLSTATE and caller behavior

Reserve **proposed** P2200–P2205 after checking all merged migrations before DDL:
P2200 malformed arguments/unsupported isolation; P2201 uniform unavailable scope
or caller; P2202 identity/digest conflict; P2203 stale holder/fence/lease;
P2204 counter exhaustion; P2205 unsafe configuration. Fixed messages only, no
SQL details or private scope identifiers. Normal busy/not_due/done are typed
results, not errors. Revocation/mismatch terminal transitions return fixed results
only after their durable transaction commits. A denied helper exception caught by
a wrapper must not accidentally retain unvalidated data in its response.

40001/40P01 roll back and retry the whole bounded transaction with identical IDs,
up to three attempts within the request deadline; 55P03/57014 roll back and return
retryable transport failure without inventing a business receipt. If a claim had
already committed, its eventual lease recovery accounts for abandonment exactly
once. Unknown commit: reconnect and inspect operation through scoped claim/status
semantics before any new effect; never interpret a lost response as noncommit.
HTTP acknowledges only committed success/terminal outcome, otherwise non-2xx.
Workload OIDC rejection does not invoke SQL or acknowledge a durable business result.

## Source review and alternatives

Sources reviewed 2026-10-13, selected sections only; proposed project decisions,
not vendor guarantees. Existing [BW01–BW05](../research/background-work-sources.md)
and bibliography S08/S12 remain canonical pattern/identity/transport references.
This section is the source record for the additional physical choices:

- **WS01**, PostgreSQL Global Development Group, PostgreSQL 17
  [SELECT: Locking Clause](https://www.postgresql.org/docs/17/sql-select.html#SQL-FOR-UPDATE-SHARE),
  paragraphs on SKIP LOCKED and joined relations. Queue scans can avoid row waits,
  but produce an inconsistent view. Our inference is bounded candidate discovery
  plus fresh authorization and locked predicates; not a fairness or ordering proof.
- **WS02**, same publisher/version,
  [Date/Time §9.9.5](https://www.postgresql.org/docs/17/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT),
  transaction/statement/clock distinctions reviewed. Actual clock time changes
  within statements; transaction time does not. Our lease check samples actual
  time after locks; application-supplied time is rejected. Clock monotonicity is
  not established by this documentation.
- **WS03**, same publisher/version,
  [CREATE FUNCTION: Writing SECURITY DEFINER Functions Safely](https://www.postgresql.org/docs/17/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY),
  search-path and PUBLIC execute paragraphs reviewed. Isolate trusted object
  resolution and revoke default invocation before commit. Our inference uses
  explicit login-bound entrypoints; the source does not verify our grant model.

A simpler single atomic observe call could omit consumer lease/attempt state,
but would not exercise the selected recovery/fencing boundary before provider
work. This fixed handler intentionally proves those mechanisms without financial
side effects. A universal JSON jobs table would add undefined authority and
migration surface; provider-specific records remain in their separate contract.
